Dating Platform

A dating platform with a trust & safety console at its centre, a website and a mobile app. Three documents: one for what the product is and how it behaves, one for the people running the console, and one for tools.

For owners, then operators, then engineers

The product

What it is and who it is for; the whole flow on one chart, in plain language, with the mobile app as a lane through it; every round trip from the app to the console and back; and, collapsed underneath, twelve engineering diagrams with the file and line each arrow comes from.

For the people running it

User manual

Every console screen, step by step, with screenshots: verification, cases, enforcement, billing including the app stores, notifications, masters and locations, settings — plus a go-live checklist.

For tools and app developers

API reference

Every /api/v1 endpoint with its authentication, token ability, parameters, request and response schemas, error codes and throttle bucket — rendered from openapi.yaml, which a test keeps in step with the routes.

Offline and on paper

Everything here works from the docs/ folder with no server: the diagram renderer, the API viewer and the YAML parser are vendored in assets/. Open a document and print it (Ctrl+P, “Save as PDF”): collapsed sections open themselves for printing, sections start on fresh pages and screenshots are kept whole.

The repository's README.md covers installation and development; scripts/docs-screenshots.mjs re-takes the screenshots and scripts/docs-verify.mjs checks every page renders and prints.
